# Apex ACC Attestation Authority

This public repository contains the Authority-v2 pre-issuance candidate for three separately keyless-signed freshness subjects over the same existing Clerk development-instance fingerprints. It contains no raw Clerk value, secret, token, PII or customer data.

## Candidate handoff state

- Independent pre-issuance approval: pending; `approval=false`.
- Final Authority decision: `approved=false`, `release_authorized=false`, closure `F12=false`. Closures F1-F11 are closed only once the sealed chain reaches `ready`; before that, closure `F8=false` as well, because F8 asserts an authenticated source chain that cannot exist until one exact authorized attempt-1 run head, tree, artifact, envelope and receipt digest are deterministically pinned. Every open closure is recorded once in `findings`. The strictly distinct activation-only decision is external and post-candidate: before the activation state is `ready` every contract and receipt carries `activation_authorized=false` with `activation_findings=[{F8, F8-AUTHENTICATED-SOURCE-CHAIN-UNAVAILABLE}]`, and only an authenticated external review moves it to `activation_authorized=true` with `activation_findings=[]`, authorizing the exact acc-releaser activation and never implying final approval. The canonical policy, both sealed bootstrap contracts, the exporter, the independent verifier and the Authority verifier all require exactly this; a receipt asserting `release_authorized=true`, a closed `F12`, or a closed `F8` while the activation state is not `ready` rejects. F8 may close only in a later fresh ordinary non-merge direct-child candidate whose `ready` bindings pin every required live field.
- Protected identity asset: private, integrity-bound, directory 0700/file 0600; only redacted booleans and SHA-256 are public.
- Subjects, bundles, workflow dispatch, signing, publication, secrets staging and release actions: none.
- Incremental spend, production/database/principal/customer/contact actions: none.

## External authority lifecycle

1. The builder commits one ordinary non-merge direct child of the freshly verified public authority base.
2. An independent reviewer recomputes the exact repository, base/head/tree/sole parent, canonical binary full-index diff, complete status-aware object manifest, policy/schema/manifests, protected-asset receipt and F1-F12 closure. `protected-source-bootstrap-v2` and `independent-review-bootstrap-v2` seal every export workflow, export helper, review workflow and validator byte. The review workflow takes no caller input at all: the authorized protected-source run, its head, the source bootstrap commit/tree, the artifact/envelope/receipt digests and the independent bootstrap commit/tree come only from the immutable sealed contract, and every executed byte is rehashed at those pinned heads before signing.
3. The separate releaser may fast-forward only those exact reviewed bytes to `refs/heads/main`. It dispatches attempt 1 with candidate bindings, the exact independent-review run ID and receipt SHA-256, unique 64-hex nonce, and immutable release tag/name. The Authority downloads the receipt and bundle itself, validates the independent run and exact sealed workflow bytes, re-derives the whole source/validator execution chain from the sealed contracts, and verifies the pinned Sigstore identity together with a certificate GitHub workflow SHA equal to the pinned independent bootstrap commit. The live independent bootstrap commit and tree are never read from the sealed pre-live contract, which keeps them `null`: the signing workflow derives both from authenticated canonical GitHub repository, run, job, commit and tree readback for the unique authorized attempt-1 reviewer run, binds the sealed workflow, validator and bootstrap-contract path-to-blob digests at that live head, and only then confirms that the dispatched run and its head are exactly the authenticated ones. A guard comparing the live head to the deliberately unavailable sealed constant could only fail closed, so it may never appear.
4. The `attestation` GitHub Environment records an independent approval with prevent-self-review. The workflow reads the exact GitHub run, job and approval history from the documented run-scoped endpoint, retaining only documented `environments`, `state` and `user` fields. Deployment IDs/statuses are omitted because GitHub documents no server-owned joint deployment/run/job relationship; caller-settable `log_url` is never relationship evidence.
5. Receipt signature, exact candidate and issuance bindings, and all three closed subjects are validated before the first keyless `sign-blob`. Publication is unavailable: after revalidating held assets, receipt/issuance and Cosign, the verifier fails closed and performs no draft, asset, tag or claim write at all. What remains is a read-only, exact and idempotent reconciliation that discovers any existing draft ID, durable claim, final tag, asset plan and guards.
6. A separate independent post-issuance review verifies the signed subjects, bundles, Rekor trusted times, tag, release, readbacks and cleanup. Issuance never self-approves.

## Trust invariants

- Canonical diff bytes are exactly `LC_ALL=C git diff --binary --full-index --no-ext-diff --no-abbrev --find-renames=50% --src-prefix=a/ --dst-prefix=b/ <base> <head> --` stdout.
- Candidate and release manifests are reconstructed byte-for-byte; CRLF, missing final LF, missing/extra/duplicate paths and object mismatches reject.
- Attempt 2+, replay, copied receipt/artifact, cross-candidate bindings, wrong repository/ref/workflow/environment/actor, self-approval, forged or caller-supplied envelope/receipt bytes, caller-selected source runs and mismatched claim/draft/asset/guard rereads reject. Replay state is a fixed protected GitHub ref, not process memory.
- The Environment custom-policy endpoint must return documented HTTP 404 in protected-branches mode. That mode is not described as main-only; the workflow independently enforces `refs/heads/main`.
- Environment evidence distinguishes an authenticated HTTP 200 read from an unauthenticated or permission-masked 404 and from confirmed absence. The sealed read-only state is HTTP 200, Environment id `20467803126`, exactly one required `User` reviewer `chrizzatsu`, `prevent_self_review=true`, `protected_branches=true` and zero Environment secrets; any live difference fails closed. A 404 becomes confirmed absence only through a deterministic bounded exhaustive traversal of the exact `/repos/{owner}/{repo}/environments` listing at `per_page=100`, capped at 100 pages, made by the *same* authenticated credential identity that issued the target Environment read on the *same* repository: every page an authenticated HTTP 200 on its exact deterministic page path, each `rel="next"` target the same endpoint at exactly the following page with the same `per_page`, every advertised page full, one consistent `total_count` matching the entries actually observed, no repeated or unadvertised page, no duplicate Environment and at least one Environment seen. A missing or mismatched credential/request identity, an incomplete or unterminated traversal, a substituted or unadvertised page, a duplicate, unparsable, foreign, non-monotonic or looping `Link` header, inconsistent totals, and a listing naming the sealed Environment all yield `masked_or_absent` and fail closed. No GitHub write is performed.
- Guard GETs use only a distinct Environment-gated GitHub App installation token requesting Administration read; the repository transport is restricted to GET and can service no guard read. The reviewed App prerequisite is currently `unavailable`, with no fallback.
- GitHub documents neither a durable server-owned pre-draft publication state, an atomic draft-to-immutable transition, nor a complete proof excluding every competing release/asset/tag writer. No documented release API establishes an exhaustive exclusive/compare-and-swap/atomic transition binding the exact activation SHA and verified immutable asset snapshots against every authorized writer, so F12 and `release_authorized` stay false, publication is `unavailable` and every draft creation, asset upload, tag creation and durable claim write is prohibited outright. `publication-writer-exclusion-v2.json` seals that exact impossibility together with the non-exhaustive known-writer model and its limits. Self-asserted or locally simulated exclusivity is rejected outright. No such write exists in the verifier or the workflow, and no contract claims otherwise.
- Documented HTTP 201 on Create a reference is the only creation. HTTP 409, HTTP 422, transport ambiguity and every other non-201 outcome are non-authoritative: 422 is never unique already-exists proof. A claim is authoritative only after an authenticated readback resolves a nonce/issuance/plan-bearing annotated tag object with the exact tag-object SHA, object type, tag name, message, commit target and request identity. Direct commit refs, lightweight tags, object substitution, collisions, foreign nonce/issuance/plan and masked or ambiguous reads all reject.
- A ref 404 is confirmed absence only after a deterministic bounded exhaustive traversal of the exact `git/matching-refs/tags/` endpoint by the same authenticated credential: every page an HTTP 200, pagination metadata well formed, monotonic and non-looping, every ref carrying the exact `refs/tags/` prefix, and explicit proof that the documented last page was reached. A target hidden on a later page, a truncated or unterminated traversal, a malformed or contradictory `Link` header and any page-fetch failure all classify as `readback_ambiguous` and prohibit every retry and write progression. All traversal requests are read-only GETs.
- Trusted evaluation time comes only from the successfully verified Sigstore bundle's Rekor `integratedTime`.
- Cosign v3.1.3 is digest/build/platform pinned and executes through one immutable verified snapshot.
- Certificate identity, issuer, repository, ref, exact workflow SHA and `workflow_dispatch` trigger are checked.
- No local key, self-signed key, private-key fallback, overwrite, bypass or alternate trigger exists.
- The public workflow remains server-disabled. Enabling it is insufficient: the sealed protected-source and independent-review chain and the guard-App prerequisite must first be independently pinned and proven, and publication stays prohibited until documented server semantics make every fallible write exactly reconstructable.
- `source-chain-activation-v2.json` separates one immutable pre-activation authorization from the post-activation proof. The grant reaches only the named `acc-releaser` activation lane, and only to create exactly `chrizzatsu/acc-authority-protected-source` and `chrizzatsu/acc-authority-independent-review`, write exactly the seven sealed bootstrap files and bytes, keep zero-spend reversible settings with workflows disabled until authenticated readback, and execute at most one exact non-caller-selectable authorized attempt-1 activation. Authority issuance, merge, signing, release, publication, product/customer/database access, external send and spend all stay false. F8 stays false and no live evidence exists; only the deterministic pinning helper may bind real repository/run IDs from a later fresh ordinary non-merge direct-child candidate.
- The seven sealed bootstrap bytes are executable and internally state consistent, with no circular readiness. Both contracts ship in the distinct `authorized_pending_evidence` state: the immutable pre-activation authorization pins the reviewed repository, workflows, helper and validator blob bindings and exactly `run_attempt=1`, while every live identifier (run id, run head, trees, bootstrap commits, artifact/envelope/receipt digests) stays unpinned and is derived at runtime from authenticated non-caller-selectable GitHub server state. A later exact pinning may fix those values, and any sealed value that then contradicts the authenticated state fails closed. Post-activation proof, `live_evidence_pinned` and F8 stay false until that later pinning, in the activation package and in every contract and receipt the pre-activation chain can produce: the sealed review result records `F8-AUTHENTICATED-SOURCE-CHAIN-UNAVAILABLE` as an exact open finding beside `F12-EXCLUSIVE-PUBLICATION-UNAVAILABLE`, and the exporter, the independent validator and the Authority verifier all reject `authorized_pending_evidence` with F8 closed. The protected lane takes no caller input at all: every path is a constant in the sealed checkout and every run fact comes from the authenticated Actions server environment, and it writes the exact envelope/receipt artifact members exclusively. The independent lane re-derives the same pre/post activation state from the authenticated protected-source contract at the pinned head, with no caller-selectable path, run, state, artifact or byte. Both fail closed while the sealed contracts remain `unavailable`.
- Terminal activation facts are produced only by `independent-review-bootstrap-v2/.github/workflows/readback-authority-v2-activation.yml`, a distinct inputless `workflow_run` collector that listens only to completion of the review workflow and rejects its initial `workflow_dispatch` run. Its read-only root filesystem is the public `python:3.13.7-slim` linux/amd64 image at exact OCI manifest digest `sha256:2be5d3cb08aa616c6e38d922bd7072975166b2de772004f79ee1bae59fe983dc`; the workflow launches only `/usr/local/bin/python3 -I -B`, keeps `PATH` deliberately unusable, fetches the contract, collector workflow and verifier from the authenticated immutable `GITHUB_SHA`, and requires their exact contract hashes before executing the verifier's stdlib-only collector phase. No ambient `gh`, `jq`, Git, archive or coreutils command decides acceptance. The collector downloads the public Cosign v3.1.3 linux/amd64 release only through its constant URL, authenticates it by the separately pinned SHA-256 before every explicit-path execution, and preserves the exact signing identity and route. With Actions/content read and OIDC signing permissions only, Python re-reads the completed activation run and job, the persisted final cleanup step and disabled workflow state, selects exactly one non-expired generated artifact by canonical server id, rechecks its server digest, archive size, archive SHA-256, closed content digest and contained `activation-record.json` digest, and then signs the closed receipt with Cosign v3.1.3 under the collector workflow's pinned Fulcio identity. Before the exact two-member upload, one binary-safe high-signal scanner rejects Authorization, GitHub token, PEM/private-key and AWS credential forms in either member, including placeholder-shaped secret bytes. The production terminal verifier accepts neither the activation workflow's identity nor caller-supplied terminal facts.
- Activation authorization is external and post-candidate. The candidate defines the receipt contract in `external_activation_review` and pins no candidate head, tree, trust digest or receipt digest of its own: `receipt_sha256` is `null`, `state` is `unavailable` and `activation_authorized` is `false`. `verify_external_activation_review` consumes immutable external independent-review receipt bytes, requires a literal `APPROVED` decision with an integer zero finding count, refuses a candidate-owned or self-reviewed receipt, and recomputes the repository, base, head, tree, sole parent, canonical binary full-index diff, complete status-aware changed-path manifest, every tracked and critical artifact digest and the current `reviewer-authorization-v2.json` bytes from the exact clean checkout. A candidate that already carries the digest of its own later receipt is refused as a circular precomputation.
- F8 has no caller-controlled switch and no caller-supplied capability. `scripts/pin_source_chain_activation_v2.py` exposes exactly one production entry point, `derive_activation_closure`, which accepts no transport, no trust material, no evidence object, no closure flag and no run identifier. It loads the pinned Sigstore trust from the candidate's own contract bytes, instantiates one fixed HTTPS read-only GitHub REST client for itself, selects the unique authorized attempt-1 runs from exhaustive authenticated listings, and reads canonical GitHub responses: canonical numeric repository, run, job and artifact identifiers each confirmed through their own canonical API URL, complete permission and API-version provenance on every read, exhaustive terminated pagination on every collection, attempt 1 with the expected successful workflow and job on `refs/heads/main` under `workflow_dispatch`, the exact sealed path-to-blob membership in the live tree at both live heads with every blob re-hashed to its Git object name and sealed SHA-256, immutable artifact download by canonical artifact id only across the two documented boundaries - the authenticated `api.github.com` artifact-id ZIP endpoint answers exactly one redirect, whose `Location` is validated strictly against the approved signed GitHub artifact storage origin class and then read over verified HTTPS with no credential, no API version, no GitHub header, no further redirect and a hard byte bound - and byte recomputation of the artifact, envelope and receipt. Synthetic identifiers, repeated placeholder digests, non-200 API reads, a direct `200` where the documented artifact redirect belongs, an absent, repeated, relative, plain-HTTP, credential-bearing, fragmented, foreign or unsigned redirect target, a second redirect, storage bytes that do not match the authenticated artifact size and GitHub SHA-256 digest, unsafe or duplicated archive member paths, mutable download URLs, missing pages or permissions and substituted trees, blobs, runs or repositories all fail closed.
- The Sigstore boundary performs real trusted cryptography, never a locally asserted success object: the leaf chains to an exactly pinned Fulcio root, is valid at the Rekor integrated time and really signs the exact subject bytes; the transparency entry binds those bytes and that certificate; its signed entry timestamp and its checkpoint verify against the pinned Rekor key; and the RFC 6962 inclusion proof recomputes the signed checkpoint root before any Fulcio workload claim is enforced. The trusted time is bound to the authenticated run and job timeline rather than to a completion instant: cosign signs and Rekor integrates the entry while the job is still running, so the Rekor `integratedTime` must fall inside the intersection of the latest authenticated start bound and the earliest authenticated successful completion bound of that exact run and job. Missing, unparsable, contradictory, non-monotonic or out-of-run timestamps, and an integration before the start or after the completion, all fail closed. The trust material is the official `sigstore/root-signing` `targets/trusted_root.json`, vendored into `reviewer-authorization-v2.json` and bound to its immutable source repository, commit `ba3066c420970c13772ba0625f09f1ec97193116`, path and SHA-256 `6494e21ea73fa7ee769f85f57d5a3e6a08725eae1e38c755fc3517c9e6bc0b66`. Nothing is fetched at runtime, no caller may supply a root or a key, and only the roots and log keys valid at the entry's integrated time are used.
- The sealed exporter emits, and the independent validator independently re-derives, the complete Authority candidate contract the production receipt validator requires: repository, base, head, tree, sole parent, canonical binary full-index diff, the status-aware changed-path manifest with modes, object ids and rename semantics, the tracked internal manifest and the critical artifact digests, together with the strict activation-only decision and the exact artifact/envelope/receipt chain. Both lanes materialise the authenticated Authority checkout at a constant path and read it only through Git.
- `publication-writer-exclusion-v2.json` additionally seals the authoritative documented semantics (`201` created, `409` conflict, `422` validation failure, and the absent release compare-and-swap) with the explicit note that no status proves exclusivity, and seals the exhaustive live authorized-writer proof as unavailable: the required proof, why GitHub cannot provide it, and each attempted inventory endpoint with the exact reason it is insufficient. `proof_available` stays `false`, the writer set stays unbounded, and a simulated or self-asserted proof is rejected.

- The reviewer's decision reaches the lane only through one sealed post-candidate delivery path it can authenticate end to end. `--phase decision-delivery` composes `authenticated/reviewer-decision-delivery.json` exclusively from read-only GitHub GETs at constant paths, and `--phase external-review` then authenticates the writer identity (a real `User` reviewer login that is both author and committer of a verified-signature delivery commit), the exact `decisions/<authority head>.json` path the lane derives for itself and never reads out of the evidence, the delivery commit and tree against the authenticated independent bootstrap head, the blob object name recomputed from its own bytes, a protected delivery branch with enforced admins, required signatures and no force pushes or deletions, and one independent readback that reproduces the exact bytes on disk. `source-chain-activation-v2.json` names that exact delivery in `pre_activation_authorization.authorized_decision_delivery`, and the receipt binds it. A decision file that merely exists in the checkout authorizes nothing, and no test-only injection can stand in for the delivery.
- No external activation review receipt exists before every canonical server object does, and none of that provenance is ever synthesised locally. `--phase server-objects` reads only raw `gh api -i` captures - the exact status line, header block and body of every authenticated read, recorded at a constant path together with the exact URL requested - and follows the server's own `rel="next"` until the traversal terminates, so no fixed page set is ever assumed. The sealed document is a deterministic function of those captures: the canonical numeric repository id and full name, the complete run, job and artifact inventories with their real status and Link provenance, the canonical commit tree and every required blob fetched by object id and rehashed, the server-returned artifact id and archive digest consumed verbatim, and the token `repository_selection` from an authenticated `/installation/repositories` read beside the `x-accepted-github-permissions` provenance the server itself required. The external-review phase recomputes that same document from the captures and refuses any document that differs, so an absent header, a non-200 status, an omitted or unadvertised page, a substituted next target, an unavailable provenance or an invented placeholder can never reach a receipt.
- The derived closure is one indivisible production operation. `pin_source_chain_activation_v2.py --phase closure` authenticates the raw sealed evidence for itself - the exporter artifact recomputed member by member, the external independent-review receipt against the exact clean checkout, its Sigstore bundle against the pinned trust inside the authenticated run and job window, and the authenticated run timeline - derives F8 internally from exactly that evidence, and hands the derived package straight to the Authority boundary, which re-derives readiness and binds it. The bound object is then sealed `0444` beside the evidence and its digest is carried by the runner state, the release checksum manifest and the final evidence manifest. No caller supplies a transport, a trust anchor, an evidence object or an evidence boolean; unresolved or null evidence exits non-zero and prints nothing. The Authority issuance lane downloads both artifacts by canonical server id and digest, assembles exactly that sealed inventory and invokes it.
- The pinned Sigstore anchor is bound to the candidate's own sealed manifest rather than to a second duplicated literal: the record must hash to the entry the manifest pins, and the Authority verifier pins the manifest itself against its own sealed constant.
- Live GitHub provenance is captured, never synthesised, and a token grant is never inferred from an endpoint requirement. The candidate supplies no grant evidence at all: `authorized_credential_grant_contract` ships `state: unavailable` with every live field null, so the shipped default fails closed with F8 false. The actual record is an external immutable artifact - the raw captured response of an authenticated read-only GET on the canonical `/app/installations/{installation_id}` endpoint, performed by the provisioner credential that alone can read it. The lane reads the issuer, installation id, the actual permissions, the repository selection and the response freshness out of those exact bytes, binds them to the runtime installation readback by exhaustive numeric repository id and full name, and binds the record digest into the receipt. Absence, a placeholder, substitution, staleness, a future-dated response, a wrong issuer, installation, repository, permission set or digest all fail closed. `x-accepted-github-permissions` remains an endpoint requirement only.
- Publication verification has a write-free verify-only path that runs every reachable publication leg for real, with no patch, bypass or stand-in: the exact release asset inventory, every asset's bytes, the release checksum manifest recomputed byte for byte, the preissuance receipt digest binding, the reviewed public asset byte streams and the writer exclusion contract. The deep plan leg re-derives the candidate through the pinned source chain, so while that chain is unpinned the path returns a truthful verified *blocked* result naming `F8-AUTHENTICATED-SOURCE-CHAIN-UNAVAILABLE` rather than a patched success. Either way the result is non-authorizing, no transport is constructed and no write is reachable.
- Every read is a raw `gh api -i` capture parsed CRLF-safely, `rel="next"` is followed until the server terminates the traversal, the same exhaustively captured run set drives selection and receipt creation, and the artifact is selected across every traversed page and then downloaded by canonical id with its size and `sha256:` digest recomputed over the obtained archive bytes. No request URL is ever written by the lane.
- Every protected-source and independent-review checkout uses `persist-credentials: false` and crosses an all-scope Git boundary before exporter, candidate or dependency execution. The boundary enumerates effective extraheaders with value-free origin/scope evidence and fails closed on any inherited header; a clean path isolates HOME, XDG, global and system configuration, clears legacy command injection and replaces `GIT_CONFIG_COUNT/KEY/VALUE` with one empty command-scope `http.extraHeader` reset that persists across later workflow steps. Credential values are never logged.
- The reviewer owns the delivery. The decision arrives as a commit in the reviewer's own repository, and the lane authenticates the writer identity, the parent, the exact internally derived `decisions/<authority head>.json` path and that this commit really introduced or changed that blob, before any decision counts.
- The release evidence inventory is one set. The three signed subjects with their bundles and the sealed runner state are bound identically by the release checksum manifest, the final evidence manifest and publication verification. Publication is confirmed with a write-free verify-only path that states the expected `F12=false`, so the run reaches a truthful terminal state instead of being forced to fail; the runner state is written only after every non-mutating gate has succeeded, and a failure path reports the state it really reached.
- The reviewer decision delivery proves who wrote it. Branch protection is read with a dedicated administration-read installation token and captured raw, so the server's own scope statement travels with the evidence, and the delivery commit must carry exactly one change to the internally derived `decisions/<authority head>.json` whose blob is the delivered one. The reviewer repository posture matches the activation package exactly.
- The runner state is produced only at the truthful terminal point, after every subject is signed and every bundle written. It derives the exact `base..head` candidate commit count from the immutable checkout, binds the derived activation closure digest, joins the release checksum manifest and is bound by the final evidence manifest. A failure path reports the terminal state it really reached and never claims `completed` in advance.
- The complete final evidence set is sealed only once nothing may still change. After every subject, every Sigstore bundle and the release checksum manifest exist, `build_authority_v2.py --seal-final-evidence` writes the post-seal manifest, seals the whole directory to `0555` with `0444` files, reads both modes back from the filesystem and recomputes every digest from the sealed bytes. Sealing earlier and appending a mutable artifact afterwards is refused outright.
- One real command line path derives F8 from live evidence rather than from a flag. `scripts/pin_source_chain_activation_v2.py --phase closure` authenticates the sealed exporter artifact, the external independent-review receipt against the exact clean Authority checkout and its Sigstore bundle against the pinned Fulcio and Rekor trust inside the authenticated run and job window, and only then derives the closure and hands the derived evidence straight to the Authority derivation. Unresolved or null state exits non-zero and prints nothing; a candidate-declared `ready`, a candidate package flag and a syntactically valid hash are never evidence. The default `--phase report` still reports `f8_closed=false`.
- Evidence generation records one internally consistent runner state and seals what it regenerates. `scripts/build_authority_v2.py --emit-runner-state` derives the exact head, its tree and the reachable commit count from the immutable checkout and records them beside the recovery round and terminal state, so a downstream receipt or manifest can bind it without contradicting the candidate. `--runner-state-dir` and `--seal-evidence` seal the regenerated directory to `0555` with `0444` files, read both modes back from the filesystem and recompute every digest from the sealed bytes.

- The reviewer's decision is not authored by the candidate. This repository defines only the decision schema, the identity and binding requirements and a fail-closed verifier; the concrete decision bytes are a separate immutable artifact the independent reviewer writes to `decisions/<authority head>.json` in its own repository, a path that cannot even be named before this exact candidate exists. `--phase external-review` authenticates those bytes - canonical exact JSON, the exact document type, a literal `APPROVED` with an integer zero finding count, `candidate_owned=false`, `produced_after_candidate=true`, the reviewer profile and a reviewer repository that is not the Authority - and requires the repository, base, head, tree, sole parent, canonical binary full-index diff and current reviewer-authorization digest it carries to equal the values the lane recomputes for itself. It then copies the reviewer's decision verbatim into the receipt. An absent, malformed, non-canonical, contradictory, candidate-owned or differently bound decision leaves the activation unauthorized.
- The reviewer really can produce what the Authority consumes. Once the exact candidate exists, `independent-review-bootstrap-v2/.github/workflows/review-authority-v2.yml` runs `--phase external-review`, which recomputes every binding from the authenticated Authority checkout and writes `external-activation-review-receipt.json` exclusively with a literal `APPROVED` decision and an integer zero finding count; the workflow then signs it, verifies the certificate binds this pinned commit, and uploads `authority-v2-external-activation-review-t_c298fca4` with the receipt and its Sigstore bundle. Both sealed contracts and the Authority verifier require exactly those artifact names, members and steps, so the transition the production operation gates is really producible.
- No candidate-owned artefact pre-asserts the activation authorization. The protected-source bootstrap contract, the exporter, the independent validator and the Authority receipt validator all require `activation_authorized=false` with the exact activation finding at any state before `ready`, and `activation_authorized=true` with zero activation findings only at `ready`.
- The authorization transition is derived, not declared. `derive_activation_closure` moves `external_activation_review.state` from `unavailable` to `authenticated`, binds the verified receipt digest and sets `activation_authorized=true` only after the external receipt bytes, digest and Sigstore provenance and every canonical repository, run, job, commit, tree, path, blob and artifact proof have passed. The activation verifier couples the three: an authenticated review requires a `ready` state, `f8_closed=true` and complete live evidence, and an unavailable review forces `activation_authorized=false`.
